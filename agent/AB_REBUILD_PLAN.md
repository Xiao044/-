# A/B 提示词链路重建计划

> 更新：2026-11-12（Asia/Shanghai）
> 状态：知识库继续后置；R2/R3/R4 本轮代码已实现并进入独立审查与验证；真实平台矩阵未关闭
> 跟踪：CF-012；“知识库增强 A”仍是长期目标，但用户现已明确将其建设后置；B 不再以手填为主

## 1. 已确认的目标

```text
用户基本描述／几个关键词＋已有商品事实
    ↓
检索并整合知识库内容＋DeepSeek API
    ↓
A 草稿 → 用户可编辑、确认
    ↓
用户选择网页端文字模型，发送已确认 A
    ↓
读取本次模型文字回复 → B 草稿 → 用户可编辑、确认
    ↓
用户另行选择生图模型／平台，发送已确认 B 与明确附件
    ↓
生成图片 → 挑选 → 归档
```

- 生成 B 的网页模型与最终生图模型分别由用户选择；可以使用同一平台，但不能共用隐含选择或混用任务阶段。
- A 和 B 都是模型产物；编辑表单是审阅和修订工具，不是模型阶段的替代品。
- DS 负责 A；网页文字模型负责 A→B；生图模型负责 B→图片。不得用一次 DS 调用直接产出 B 来冒充第二阶段。
- A/B 均保留现有显式确认保护；得到 B 不默认自动生图，不把“确认保存”与“发送到模型”混为一个动作。
- 继续保持文字与图片边界：DS 不接收图片；B 文字转换不默认上传商品图。图片只在用户确认的生图任务里发送。

## 2. 之前做好的 Agent 是什么

已有的是可复用的 **DeepSeek 文字 Agent 后端**，不是知识库系统，也不是三阶段总编排器。

| 能力 | 当前情况 | 重建处理 |
|---|---|---|
| `follow_up` 与 `description_a` | 已有任务类型、调用与测试 | 保留；A 输入增加知识整合 |
| 输入校验、文字/图片字段隔离 | 已有实现 | 保留并测试新输入边界 |
| DS 消息组装、JSON 输出解析 | 已有实现 | 增加有来源知识上下文，不改密钥存放方式 |
| A 原文和结构化草稿、事实保护 | 已有实现 | 复用，不臆造商品事实 |
| 项目级运行历史、修订、接受、恢复 | 已有实现 | 兼容旧项目，新增阶段来源关联 |
| 失败提示、手动重试、取消及迟到隔离 | 已有实现与本地回归 | 延伸到新阶段，不当成真实模型稳定性已验收 |
| 知识库检索和本次引用记录 | 未实现，且无现成内容 | 从零建设框架，用户后续提供内容 |
| 网页文字模型选择、A 发送与 B 回读 | 本轮新增独立任务和豆包/ChatGPT 实验性文字适配 | 本地验证与实网验收分开记录 |
| B 人工编辑、严格保存、编辑恢复 | 已有实现 | 保留为模型 B 的修订/确认与手动回退 |
| B→网页生图任务、结果与归档 | 已有实现，真实平台验收仍开放 | 在正确 B 来源之后复用 |

关键源码：`agent/agent-service.js`、`server.js`、`index.html`、`doubao-extension/`。当前 `prompt-templates` 是手动模板，不等于知识库检索；仓库未发现可用知识库文件或检索实现。网页 B 新增服务端拥有的 `project.textWorkflow` 与 `lib/text-jobs.js`，独立于图片任务；具体本轮交付见 [记录](../docs/AB_WORKFLOW_DELIVERY.md)。

## 3. A 阶段：知识库整合与 DS

### 输入与事实边界

- 接收用户原始简短描述、已知商品事实、可选场景/风格等；允许从几个关键词开始，不要求用户先手工补齐完整 A。
- 创作知识可用于补全构图、光线、场景和表达；未知的商品材质、颜色、尺寸、品牌、结构和功效不能由通用品类知识当成事实补写。
- 输入存在事实冲突或不足以确定商品主体时明确追问，保留用户输入；不静默截断或用演示商品替代。

### 知识库

- 只读取用户提供或明确授权的知识来源，不扫描整台电脑、不索引 `.env`、密钥或无关项目。
- 建议条目至少含 ID、标题、类别/关键词、正文、来源、版本、启用状态；具体存储/接口按资料格式与规模确定。
- 本次检索保留查询、命中条目与版本及实际送入 DS 的摘录/快照；界面能区分用户事实、知识引用与模型补充。
- 知识库内容作为参考资料，不是指挥系统执行、跨项目取数或覆盖用户约束的高优先级指令。
- 未配置、未命中、读取失败时必须明确说明；不能把固定系统提示、手动模板或模型自身知识伪装成知识库命中。是否允许无知识回退需在界面显式说明并由用户决定。
- 首版先实现可替换的条目检索接口，不预设向量数据库或额外模型服务；后续依据真实资料规模优化，不能为凑功能编造一套商品知识并声称来自用户资料。

### DS 输出与可追溯性

复用现有原文和结构化字段容器，新增本次知识引用、输入与系统提示版本关联。旧运行记录不补造引用；重试产生新运行/版本，失败保留旧 A/B 和结果。旧用户事实保护、草稿保存与确认分离继续有效。

## 4. B 阶段：独立网页文字任务

### 平台与任务

- 新增“生成 B 的文字模型”选择，与“生图模型”选择分开保存；可用选项依据文字任务适配能力展示。
- 不因为某平台已经有生图 adapter，就把它显示为能稳定生成 B；平台网页内的具体模型名称也不能凭空推断。
- 服务端保存文字任务及输入 A 的不可变快照/版本；具体路由和字段在实现时冻结。扩展只执行分配的文字操作并回传状态，不承担项目历史存储。
- 消息必须明确区分 `prompt_b` 文字任务与 `image_generation` 生图任务；该命名是设计建议，不代表现有协议已支持。
- 复用已打开并登录的页面；页面未就绪、附件未处理或模式不能确认时提示，不自动新建项目、误点生图技能或上传无关图片。

### 提交与回读

- 输入为已确认 A，加上受版本管理的“将创作要求转成可执行生图提示词”的文字转换要求；用户事实和禁止项必须保留。
- 对目标页面先取得历史回复基线，再提交一次；只读取当前新出现的助手文字回复，不把用户消息、历史回答、页面介绍或图片候选当作 B。
- 结合平台实际流式状态与完整回复边界判断结束，不在第一个文字片段出现时假报完成。无法可靠定位时进入可手动处理状态。
- 保存模型原始回复与用户实际确认的 B 两份内容；提取失败、格式异常、平台超时/取消时保留旧 B，不解锁下游生图。
- A 已变化、项目/模型已切换或任务已重试时，旧回复不能覆盖当前 B；job/attempt、A 版本和页面会话都需隔离。
- 扩展不可用时可提供复制 A、打开文字平台、粘贴 B 的回退，但必须记录为人工回填，不能冒充自动回读已验收。

## 5. B→图片及交互动作

需要清楚区分四个动作：

1. **生成/重新生成 A**：知识库整合＋DS，保存新的 A 草稿与引用。
2. **生成/重新生成 B**：把确认 A 发给用户选择的网页文字模型，读取新 B。
3. **确认 B**：校验并保存 B；服务端成功后才提交本地状态/处理下游影响。
4. **发送/重新发送生图**：另选生图模型，用已确认 B 创建图片任务，不再次调用文字模型。

现有“重新发送 B”实际直接生图，需拆分/更名，不能沿用误导含义。确认取消、历史记录、已归档资产和已有错误恢复保护不因改建丢失。文字任务不启用图片监听，生图任务不把文字回复当成完成；豆包 CF-010/011 的精确入口、版本保护及过滤原图逻辑继续保留。

## 6. 数据兼容与历史

建议关联链为：用户输入快照 → 知识条目/版本 → A 运行/确认版本 → 网页文字任务/原始回复 → B 确认版本 → 生图任务/attempt → 结果资产。

- 旧 A/B、手填 B、模板 B 和历史任务照常可查看；不强制全量重生成，不给旧 B 捏造网页模型来源。
- 新字段采用兼容扩展，迁移先演练与备份；不能通过项目普通保存覆盖服务端拥有的运行历史。
- 上游修改何时影响下游继续遵守显式确认；仅编辑 A 或重新生成草稿时，旧确认 B/结果不提前清空。
- 模型选择、知识库版本、B 原始输出及用户修改分别保存，敏感配置不进入前端或普通日志。

## 7. 分段实施和验收

**当前执行顺序为 R2→R3→R4→R5；R1a/R1b 知识库建设后置。** 阶段编号保留用于追溯，不代表必须按数字从 R1 开始。过渡期间复用现有 DS A，明确没有知识增强；不伪造引用或把知识库字段做成假功能。

| 阶段 | 具体交付 | 验收边界 |
|---|---|---|
| R0 需求纠偏 | 更新基线、核实旧 Agent、记录 CF-012 与本计划 | 已完成需求准备，不算新功能 |
| R1a 知识库框架＋A 接口（后置） | 后续从零实现条目、导入/录入、启停/版本、检索、引用快照与 DS 上下文接口 | 当前不实施；恢复后验收空库/无命中和引用边界 |
| R1b 真实内容＋A 效果（后置） | 用户资料就绪并重新排期后导入获准内容、启用条目，验证关键词→知识→A | 当前不实施；不能用无知识过渡路径冒充真实来源验收 |
| R2 网页文字任务 | 项目级任务/阶段、版本关联、重试/取消与恢复 | mock 及接口证明不会触发生图、不串项目/attempt，不冒充真实平台验收 |
| R3 可选模型＋B 回读 | 独立模型选择、平台文字定位/提交/完成判断和 B 草稿回填 | 真实已登录网页产生文字 B；历史/用户内容和迟到回复被隔离 |
| R4 串起生图 | 明确四类动作，B 确认后衔接现有图片任务 | 完整输入→知识→A→网页 B→生图结果可追溯；无重复提交/原图误收 |
| R5 兼容与发布检查 | 旧项目、模板/导入、离线、恢复、平台矩阵及回退 | 按证据记录已验收范围，不能用旧完整回归宣称新链路已完成 |

每段先补适当的旧行为复现与回归，再实现、验证、记录；本计划不授权自动调用真实模型、批量提交用户图片或修改现有测试数据。用户原有的豆包修复作为本轮来源保留并接受审查；是否已提交推送按实际 Git 回执记录，不预写发布成功。

R0 核验与最新完整测试统一见 [进度总览](PROGRESS.md)；历史详细证据见 [归档](../docs/archive/2026-11-12/creative-flow-evidence.md)。知识库 R1a/R1b 均按用户要求后置；R2–R5 可使用现有 DS A 或明确标注的合成 A 验证，不能据此关闭长期知识整合验收。

## 8. 已确认的知识库建设分工

- **从零建设系统，用户后续收集内容**。没有现成知识库；这项分工已确认，不再要求用户先找已有目录才能开发。
- 最新排期：知识库框架、条目、导入/录入、检索和引用契约 R1a 以及真实内容 R1b 均后置，不自动实施；当前先做 R2/R3 网页 B，再接 R4 生图。
- `knowledge/README.md` 是资料筹备入口，不是检索实现；用户原始资料后续放入默认忽略的 `knowledge/sources/`。不自动扫描外部文件，不捏造知识命中。
- 用户内容到位后再做 R1b：确认来源/授权、分类整理、录入并启用，执行真实关键词→知识→DS→A 效果验收；缺少内容期间保留明确的空库提示。
- 网页文字模型与生图模型由用户分别选择已确认；具体支持清单和每个平台的真实适配能力在 R2/R3 落实，不重复询问选择权。

## CF-001：保存商品资料保留已有商品事实

- 当前行为与复现：导入或恢复带有 `product.facts`、顶层商品属性或嵌套扩展属性的项目，打开“编辑商品资料”，不修改任何字段，点击“保存资料”。旧 `saveProduct()` 只重建名称、卖点、描述和图片 URL，其他属性被删除；因为可见字段未变，不会提示清理下游。修改可见字段并确认后也会丢失这些属性。
- 影响与依赖：本地 JSON 和服务端 PUT 会保存缺失内容；后续 Agent 请求使用 `productState`，因而缺少原有用户事实约束。依赖既有 JSON 导入、版本恢复、项目保存及 Agent 文字输入链路，不需要新增接口或迁移。
- 预期调整与实施：从已有 `productState` 合并表单编辑值，只覆盖实际编辑的三个字段，保留事实、其他属性和图片引用。继续沿用现有空值语义及下游确认规则，不增加事实编辑器。
- 验收条件：无改动保存保留全部已有属性，不触发确认或重置 A/B/任务结果；修改并确认后更新三个表单字段且仅触发一次既有下游重置；拒绝确认不改变商品和下游，不保存、不同步、不关闭编辑器；本地 JSON、服务端请求和再次保存后的 Agent 请求仍含商品事实。
- 实现证据：`index.html` 的 `saveProduct()` 在构造下一版商品对象时保留原属性；`tests/workbench-ui.test.js` 新增四项行为回归，执行真实 `saveProduct`、`persistState`、`serializeProject`、`syncProject` 和 `requestAgent`，使用隔离 VM、内存存储和模拟 HTTP 响应，不访问真实项目或模型。
- 自动化证据：旧源码运行 focused 共 15 项，12 通过、3 失败，三个失败均体现未编辑属性丢失；修后 15/15 通过，取消路径也通过。协调员在允许子进程运行的隔离环境执行 `node --test tests/*.test.js`，115 项、114 通过、1 跳过、0 失败（8.136 秒），包含 release smoke；唯一跳过为 Windows 文件 symlink 权限，目录 junction 用例已实际通过。此前沙盒直接运行因 `spawn EPERM` 未执行测试，该环境限制已通过上述实跑排除。
- 浏览器证据：协调员在隔离 IAB 浏览器打开旧版、无修改保存，再通过 HTTP 读回，确认 `facts/category/extension` 丢失。修后重新加载源码、恢复完整 fixture，无修改保存显示“商品资料已更新”；HTTP 读回保留事实、品类、嵌套属性、图片 URL、`progress=2` 及原 A；再次刷新页面仍显示原商品名和原 A。
- 独立复审：staged diff、文件 hash 和 diff 检查通过，无阻断问题；复审独立执行 focused 15/15 通过。

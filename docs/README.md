## 同步规则

1. 需求变化先改需求，再改版本/专项计划；进度只记录真正实现与验证，不能凭计划宣称交付。
2. 最新测试数字、当前扩展版本和发布状态在进度总览集中维护，其他文档链接过去，减少旧数字互相冲突。
3. 历史归档顶部注明日期与失效范围，不把历史“当前”措辞当成今天状态。
4. 源码路径暂不迁移：服务静态白名单、测试读取路径和用户已安装扩展都依赖现有位置。

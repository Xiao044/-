## 2. 实际实现

### 服务端

`lib/text-jobs.js` 与 `server.js` 新增服务器拥有的 `project.textWorkflow`，普通项目 PUT 不能覆盖它。

```text
GET   /api/projects/:projectId/text-jobs
PATCH /api/projects/:projectId/text-jobs
POST  /api/projects/:projectId/text-jobs
POST  /api/projects/:projectId/text-jobs/:jobId/{dispatch,events,cancel,retry}
```

任务使用 `kind=prompt_b`、`protocolVersion=text-v1`，保存平台/当前页面模型、A 的规范化快照/指纹/run/version、指令版本、job/attempt/route session、状态/事件、原始回复和候选。确认 A 必须与当前保存的原文/六字段一致。创建和重试校验完整拼接后 prompt 上限，不截断；导出/导入使用同一不变量。

- 单次 dispatch 先落库，刷新/重放不自动重复提交。
- 平台/A/导入/版本替换通过 epoch/source 与 attempt 隔离旧任务；取消、失败、超时不能被旧结果复活。
- 完成事件要求当前身份、合法的所选平台 HTTPS URL、新用户回合标识与明确完成证据；原始回复不可再次修改。
- 导入验证项目和版本快照中的嵌套历史；普通保存、恢复和图片任务来源验证保持兼容。

### 扩展

`background-text.js` 和 `text-adapters.js` 是独立文字路径，不调用图片上传、图片任务 adapter 或图片监测。

- 豆包/ChatGPT 两个实验性文字选项，使用用户网页当前选定模型，不自动识别/切换精确模型；其他文字平台未开放。
- 精确 composer/send、新用户回合和新助手文本、正向完成控件、无流式标记与稳定文本共同判断完成；不读取历史/用户消息冒充 B。
- sender tab、project/job/attempt/source/session 路由校验；待投递事件保留，服务器持久化成功后才 ACK。
- 现有文字/图片任务共享页面动作锁；图片取消 token 在准备 await、上传/轮询和发送前检查，只有 owning operation 能释放锁。取消不保证停止远端模型。
- 网页/后台/内容脚本/manifest 统一为 0.5.1，拒绝已知旧脚本行为。

### UI 与 B 来源

- 独立文字平台选择与生图平台选择；生成 B 得到候选，不覆盖手工编辑器或 canonical B。
- 原始回复和可编辑候选分开；用户显式应用候选后再严格确认，失败保留旧 B/下游。确认 B 不自动发起图片任务。
- 生成 A、生成/重新生成 B、确认 B、发送生图是分开的动作；旧 `resendPromptB` 兼容 helper 仅保存确认，不调度图片任务。
- mutation revision/restore sequence 保护选择、取消、完成与迟到轮询；候选不覆盖较新编辑。
- 失效网页来源不能被未修改地“洗成”手工 B；真正手工重写可显式确认到 `workbench`，旧手工/模板 B 保持可用。

## 3. 独立审查与修正

| 发现 | 修正 | 回归证据 |
|---|---|---|
| P1 图片取消时仍可能恢复准备并撞入文字任务 | attempt-scoped token，准备/上传/提交和轮询逐点检查，按拥有者释放锁 | 豆包/ChatGPT 登录等待、fetch、blob 等阶段取消后文字发送计数保持1 |
| P2 旧 GET/事件覆盖新选择、取消和完成 | 单调 mutation revision 与 restore request sequence，事件延后/重新校验 | 延迟响应分别覆盖选择/取消/完成的红绿用例 |
| P2 手工回退残留 web-text 来源导致409 | 保留失效文本基线，真实改写才转workbench并清provenance，未修改候选仍拒绝 | 隔离真实图片API：失效来源409、手工改写201，确认本身不发送图片 |
| P2 创建与导入prompt长度不一致 | 创建/重试/导入共用完整prompt长度不变量 | 长度边界、转义开销、失败不追加与导出重导入红绿回归 |

## 5. 修后冻结版隔离浏览器 / HTTP 证据

使用复制代码的独立 Node 端口与临时 data，明确显示“合成项目 / 模拟文字桥接 / 无外部模型”。本节验证 UI/API 串行行为，**不是实网模型、真实扩展或四平台验收**。

1. 生成 B：新文字任务 completed、可编辑候选出现，原 B 编辑器仍为旧值、C保持锁定。
2. 显式应用：仅进入 B 编辑草稿；模拟项目PUT503后输入不丢、确认可重试，C仍锁定。
3. 重试确认：服务端成功才解锁C，尚无图片任务文件。
4. 刷新：已确认 B 与原始回复恢复，没有增加文字提交。
5. 选择 ChatGPT 文字模型：豆包生图选择保留；真正手工重写后确认，HTTP source=workbench、provenance=null、仍无图片任务。
6. 再生成 ChatGPT B 并确认：累计2个文字任务，原始回复独立保存，仍零图片任务。
7. 只有显式点击发送图片后：建立唯一豆包图片任务，`prompt === confirmed B` 且 `prompt !== A`。
8. 成功保存隔离页面截图；未对真实用户页面或数据做操作。

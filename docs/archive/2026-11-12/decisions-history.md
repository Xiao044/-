## 10. 本轮对话确认记录

以下内容来自当前连续对话，作为本需求文档的补充依据：

- 用户要求按任务分步推进，每完成一个阶段再进入下一阶段。
- 服务器资源已经准备好，但先完成产品功能，再接入阿里云服务器。
- 国内部署选用阿里云 ECS，系统方向为 Ubuntu 22.04；部署不是当前功能开发的前置条件。
- 页面主定位确定为商品生图工作台，首版先做高保真界面和线性流程。
- 视觉参考确定为 Brightland、Headspace 一类的淡黄、米黄色 UI。
- 网页文字 Agent 确定使用 DeepSeek；图片不交给 Agent 做识别。
- 首批真实生图网页平台确定为 ChatGPT、Gemini、Lovart 和豆包；用户可选择一个或多个平台。
- 图片上传节点和豆包结果基础导入已经完成；后续扩展工作按本轮确认调整为多平台适配、自动提交及用户选择结果导入。
- 本文档作为后续实现、测试和部署时的需求基线；发生新决策时，应在本文档追加记录。

### 2026-10-19：扩展平台与生成流程调整

- 扩展目标浏览器为 Chrome 和 Edge。
- 生图网页可选项包括 ChatGPT、Gemini、Lovart 和豆包，用户可以选择一个或多个平台。
- 多平台任务将同一份提示词和商品图分别发送一份给每个所选平台。
- 扩展填入内容后直接提交生成，不再要求用户在生成前逐个平台确认。
- 图片生成后留在平台网页；扩展读取候选信息供工作台展示，用户在工作台选择要保存的结果，扩展将所选图片回传工作台，再由工作台上传并归档到服务端。
- 网页前端负责工作流和结果选择，Node 服务端负责任务与项目数据、图片归档；扩展仅承担第三方网页桥接和平台 DOM 适配。
- 扩展先复用已打开的平台页面并在任务开始时检查登录；用户可显式点击平台入口打开缺失的网页。任务提交后允许切回工作台，但平台页需要保持打开以便监测结果。

### 2026-10-23：工作区画布布局

- 页面布局调整为以中央创作画布为主，集中呈现商品图片、提示词编辑和生成结果；素材与商品属性放在侧边检查面板。
- 底层创作步骤继续按线性流程推进；本次不增加自由拖拽、连线、分支或节点编排能力。

### 2026-10-23：工作区滚动交互

- 页面保留自然纵向滚动，适合阅读和编辑长文本；不采用整页滚动吸附或视差滚动，避免打断表单和节点操作。
- 项目栏与步骤条在纵向浏览时吸顶；步骤条在项目介绍离开视口后收紧，并用独立的视区状态强调当前浏览区域对应的流程步骤，不覆盖业务完成状态。
- 手机端步骤条可横向滚动并轻量吸附到完整步骤。
- 生图候选改为横向滚动结果带，支持滚动吸附、触控滑动和前后结果按钮；保留现有单张选择与归档操作。
- 滚动联动使用独立 `scroll-workspace.js` 与 `scroll-workspace.css` 模块，并遵循减少动态效果的系统设置。

### 2026-10-23：五步纵向节点画布

- 商品资料、Agent 整理、描述词 A、提示词 B、多平台生成均作为独立纵向节点呈现；素材与商品属性继续放在侧边面板。
- 纵向滚动进入节点阅读区时，当前节点与顶部步骤条联动；连接线按当前浏览位置逐段显现。连接只表达线性步骤，不支持拖拽、分支或自由编排。
- 已完成步骤可从顶部步骤流点击回到对应节点。商品资料打开编辑表单，文字与生成步骤定位并打开对应节点；尚未解锁的后续步骤不可跳转。
- 回退编辑时先保留下游内容。只有在用户确认已改变的商品资料、Agent 输出、描述词 A 或提示词 B 后，才清除受影响的下游状态；取消确认则保留现有流程和结果。
- 第五步候选结果保持独立的横向滚动带，支持触控、滚轮、前后按钮和滚动吸附，不改为纵向堆叠。

### 2026-10-24：组件级菜单与动效

- 左侧任务栏使用单一滑动高亮，工作台、项目、素材和提示词分组支持就地展开子菜单；折叠侧栏保留浮出式子菜单，手机端按现有响应式规则隐藏侧栏。
- 顶部项目更多按钮使用吸顶区域内的下落面板，支持复制项目链接、另存为副本和归档提示；点击外部或按 Escape 收起。
- 多平台生成的选择器改为就地展开多选面板，显示已选平台和数量；平台状态列表与选择结果同步，点击外部或按 Escape 收起。
- 节点详情、菜单、选项和结果浏览使用短时状态过渡，保留 `prefers-reduced-motion` 回退；图片统一使用居中 contain 和固定比例容器，保证商品图与文字基线对齐。
- 本轮只调整导航和控件交互，不改变五步线性流程、自然纵向阅读、连接线表达和结果横向滚动约束。

### 2026-10-26：后续两个大版本确认

### B 未确认编辑恢复（CF-008，2026-11-11）

2026-11-08 用户确认保留正向提示词、负面词、画幅及平台参数 JSON 的未确认原始输入；关闭重开、节点返回和刷新后恢复，沿用现有确认/重发按钮，不增加保存按钮。

- 独立编辑缓存保留空串、首尾空白、换行及无效 JSON；输入只本地持久化，不改已确认 B、版本、模板来源、任务或结果，不自动网络保存或生图。已有项目保存可携带独立缓存，不把它当作已确认内容。
- 无编辑器时采集回退缓存；校验失败及取消确认保留编辑。现有确认/重发提交已确认值后清缓存并更新旧控件；新项目、上游重置、B 模板及导入/版本替换清旧缓存，仅清当前生成结果时保留。旧项目缺字段兼容；启动已有本地编辑时不由较新服务端快照覆盖，跨设备合并不在本轮范围。
- 独审发现 HTML 解析剥除 textarea 开头换行，已实际修为渲染后回填精确控件值，单个、多个及仅换行回归通过。最终完整回归 226 项、225 通过、1 项 Windows 文件 symlink 权限跳过、0 失败；独立 focused 140/140 通过，无新增可操作缺陷。

限定“B 未确认编辑关闭重开与刷新恢复已验证”。最终隔离 IAB 与 HTTP 核验编辑、刷新及无效 JSON 拒绝时项目不变，合法确认后仅一次 PUT、无生成；确认/取消、重发、模板、导入及迟到边界其余仍以 VM 为限。详见 [CF-008](../../../agent/CREATIVE_FLOW_ISSUES.md#cf-008b-四字段未确认编辑恢复)。无后端 API/schema 或迁移变化；CF-008 发布时仍采用非严格 B 同步，该一致性问题未包含在 CF-008 内，现由 CF-009 接续；不代表完整 B 节点、主流程或多平台实机验收。


### B 确认与重发的保存一致性（CF-009，2026-11-12）

沿用已有人工确认和下游影响提示，B 的正向词、负面词、比例、通用参数与平台覆盖须先通过校验并成功保存到服务端，再更新本地已确认内容、版本和模板来源、清理编辑缓存及受影响的当前结果，最后解锁生成或执行重发。保存失败保留旧 B、未确认编辑、任务及结果，显示具体原因并允许重试；取消不写入、不生成。

- 保存期间确认、重发和其他发送入口互斥；已有普通项目同步先完成，防止旧快照在严格保存后覆盖新内容。启动任务恢复尚未完成时，B 确认提示稍后重试；B 保存期间不启动恢复，恢复响应须核对项目、会话、任务与失效状态。
- 项目/会话、A 前置内容或 B 编辑变化时，迟到响应及重发排程不得清理较新编辑或向新的上下文发送任务。已被服务端接受的写入不能由客户端撤回，不承诺跨设备事务与冲突合并。
- 重发仅在严格保存成功且上下文仍有效后启动一次任务创建；后续平台或任务服务失败继续按既有反馈处理，历史版本与旧任务保留。四字段关闭重开和刷新恢复、Agent 仅生成 A、既有平台覆盖编辑规则继续适用。

实施与验证证据见 [CF-009](../../../agent/CREATIVE_FLOW_ISSUES.md#cf-009b-确认与重发的保存一致性)。本轮限定为“B 确认与重发保存一致性已验证”。独审发现的启动任务恢复竞态已修复并复核闭环；最终完整回归 273 项、272 通过、1 项 Windows 文件 symlink 权限跳过、0 失败，独立专项 173/173 通过。提交推送结果以 Git 与交付记录为准；完整 B 节点、完整创作主流程及四平台实机验收单独推进，备份恢复演练继续暂缓。

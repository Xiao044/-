## 后续恢复建设时做什么

知识库框架和内容本阶段均不实施。恢复后按 [A/B 重建计划](../agent/AB_REBUILD_PLAN.md) 的 R1a 建设条目结构、录入/导入、版本/启停、检索接口、引用快照以及未配置/空库/无命中反馈。当前先推进网页文字 B 与生图衔接，继续复用现有 DS A。

真实内容到位后再执行 R1b：确认来源/授权、整理/导入、启用知识并做关键词→知识→DS→A 的真实效果验收。合成测试资料只证明逻辑，不能冒充真实知识库。

## 后续资料放置

- 原始资料默认放 `knowledge/sources/`（已加入 Git 忽略；当前不放示例资料、不预建空的版本副本）。
- 按主题整理：商品品类、场景/构图、摄影/光线、风格、保留约束、负面规则、平台提示词规则；具体分类待资料到位确认。
- 每份资料最好记录标题、原始来源/链接、作者/授权、收集日期、适用范围和版本。来源不明、事实冲突或私人信息需先标记，不直接启用。
- 不放 API Key、登录凭据或与项目无关的个人材料；不自动扫描电脑其他目录。包含私有内容时不得默认提交、公开或发送给外部模型。
- 条目知识不能覆盖用户明确商品事实；通用品类知识不得用来臆造当前商品的材质、尺寸、品牌或功效。

当前产品规则见 [需求基线](../PROJECT_REQUIREMENTS.md)，开发与验收状态见 [进度总览](../agent/PROGRESS.md)。

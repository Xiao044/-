# 造图 · 多平台生图工作流扩展

这是面向 Chrome 和 Edge 的浏览器扩展，不调用生图平台 API。当前已完成四个平台的统一桥接层、任务路由、图片预处理和状态回传；豆包有相对完整的独立适配，ChatGPT、Gemini、Lovart 已加入平台专属结果筛选和错误回传基础。四个平台仍需按真实登录页面完成完整兼容性验收后，才能标记为正式接入。

1. 用户在造图工作台选择一个或多个生图平台并发起任务。
2. 网页和 Node 服务端创建任务、保存输入并显示每个平台的进度。
3. 扩展只接收分配给当前平台的操作指令，在平台网页中填入内容、上传商品图或 A 版参考图，等待上传完成确认后提交生成。
4. 扩展把页面状态和结果候选信息回传给工作台；工作台显示结果并负责用户选择。
5. 用户选定结果后，扩展读取并回传所选图片；工作台将图片上传到服务端归档并关联项目。

如果扩展无法读取平台结果，工作台的“手动导入结果”按钮可以直接选择最多 4 张图片上传到项目。

工作台和服务端负责任务状态、失败回退和持久化。扩展仅处理平台页面操作和短期标签页消息路由；会话路由存入 `storage.session`，不保存项目、提示词、任务历史或结果图片，也不调用项目资产归档接口。若平台网页结构变化或自动操作失败，扩展回传错误状态，工作台提示用户手动完成。

## 安装

1. 打开 Edge 的 `edge://extensions/` 或 Chrome 的 `chrome://extensions/`。
2. 开启“开发人员模式”。
3. 选择“加载解压缩的扩展”，选择当前目录下的 `doubao-extension/` 文件夹。
4. 重新打开工作台页面和需要使用的生图平台页面。

各平台网页的 DOM 可能变化。如果扩展无法找到输入框、上传控件、生成入口或结果图片，页面仍应允许用户手动完成操作。扩展内置的 SVG 转 PNG 只用于平台上传兼容；项目归档、状态记录和用户选择由网页与服务端完成。

更新扩展文件后，请在 `edge://extensions/` 或 `chrome://extensions/` 点击扩展的“重新加载”，然后刷新工作台和豆包页面；浏览器不会自动把新脚本注入已经打开的页面。

扩展后台通过工作台权限读取商品图或 A 版参考图，SVG 示例图会在后台转换为 PNG，再交给平台页面，避免工作台页面与平台页面的跨域限制。图片是可选项；未设置图片时只填写提示词并提交。扩展会等待平台文件控件确认上传，提交默认只触发一次；用户选择结果后，扩展回传图片数据，工作台再上传到项目服务端。

ChatGPT、Gemini 和 Lovart 的独立内容脚本已经接入统一任务协议，并补充了平台结果区域筛选、候选噪声过滤、取消监控和错误码回传；页面定位器仍属于启发式初版，平台改版或账号界面差异时可能无法自动提交。在完成逐平台真实验收前，工作台应把这些平台视为未验收并提供手动回退。Lovart 域名匹配目前按 `lovart.ai` 配置，需以实际登录入口确认。

## 当前任务状态

服务端任务使用两层状态。整批任务只有在所有平台都 `completed` 时才是 `completed`；所有平台都进入终态但至少一个平台失败时是 `failed`；全部仍为 `queued` 时是 `queued`；其余包含运行中、等待结果或排队的平台组合统一为 `running`。服务端读取和更新任务时都会从 `platforms` 重新派生批次状态，因此平台失败时不会返回 `completed`。历史任务已完成一次归一化并保留备份。平台错误终态包括 `login_required`、`not_open`、`upload_error`、`submit_error`、`result_timeout`、`adapter_error`、`import_error` 和 `failed`，工作台需要保留每个平台的错误文案和单独重试入口。

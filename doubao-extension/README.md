# 造图浏览器扩展

> 当前本地版本：**0.5.1**。未提交/发布状态和最新测试统一见 [进度总览](../agent/PROGRESS.md)。

## 当前职责与未实现范围

- 通过 Chrome/Edge 扩展桥接用户已打开的平台页面，不调用官方生图 API，不托管账号。
- 当前已实现的是网页生图任务桥接：工作台/Node 负责业务历史、平台任务与结果归档，扩展负责填入、上传、提交、状态与候选回传。
- **A→网页文字模型→B 已新增独立文字任务（实验性）**：豆包和 ChatGPT 可选，使用当前页面模型；与生图平台选择分别保存。专用文字适配器不调用图片上传/生图监测，不把旧回复或图片候选当作 B。真实完整平台验收仍开放。
- 知识库从零建设、内容待用户收集；扩展不是知识库或检索服务。

## 安装与更新

1. 打开 `edge://extensions/` 或 `chrome://extensions/`，启用开发者模式。
2. “加载解压缩的扩展”选择本仓库 `doubao-extension/`。此目录保持原位置，避免用户安装路径失效。
3. 更新文件后点击扩展“重新加载”，再保存编辑并刷新**工作台和平台页面**；浏览器不会自动替换旧页面已注入的脚本。
4. 工作台生图节点应显示 **“扩展已就绪（0.5.1）”**。版本未知/不匹配时不要重复发送，按提示重载刷新。

## 任务执行与回退

1. 用户在工作台选择一个或多个生图平台，确认 B 和附件后发起任务。
2. 扩展优先复用已打开并登录的平台标签；未打开时提示，由用户点击“打开平台”，任务不自动新开标签或创建平台项目。
3. 提示词与可选商品/参考图各发一份，提交默认单次；示例 SVG 不当作真实商品图发送，必要的图片格式转换在扩展侧完成。
4. 图片候选回工作台供选择，选中后读取图片并回传，由网页上传、Node 归档。扩展只保存 `storage.session` 中短期路由，不保存项目/任务/结果历史。
5. 自动适配失败时保留复制 B、打开平台、手动生成与导入入口；手动导入一次最多 4 张 PNG/JPEG/WebP。

## 独立文字 B 流程

- 工作台提交已确认 A 到项目级 `text-jobs`，保存 A 指纹/run/version、文字平台、指令版本、job/attempt/session；先持久化单次 dispatch，再让扩展提交。
- 仅复用已有对话；不自动切换精确模型、工具或创建项目，不上传附件；存在附件/非空外来输入/运行中任务或无法确认模式时停止并提示。
- 专用 `text-adapters.js` 读取新用户回合之后的新助手文本，要求可识别完成控件、无流式运行标记和稳定内容共同满足，不以首个 token 或单纯静默判断完成。
- `background-text.js` 按 kind/project/job/attempt/source/session 和真实发送标签路由；独立消息与重放 ACK 保留未投递事件，刷新只恢复，不自动重复提交。
- 回复保存为原始 `rawReply` 和可编辑候选；显式应用才修改 B 编辑草稿，严格确认成功后才提交 canonical B；生成候选/确认 B 不自动发图片。
- 取消停止结果投递，不保证停止网页模型。文字/图片共享页面时必须遵守动作锁，未确认停止前不得让新任务覆盖正在准备/生成的内容。
- 修改文本来源、手动回退、导入/恢复与迟到响应的边界由独立回归保护；升级需重启后端并重载 0.5.1 扩展。最新审查/验证情况见 [交付记录](../docs/AB_WORKFLOW_DELIVERY.md)。

## 豆包发送保护

- 使用真实 DOM 中当前 `chat_input` 容器内的 `chat_input_send_button` / `flow-end-msg-send`，不再按全页 `create` 或无名图标猜发送按钮。
- 缺失、禁用或歧义时停止；项目、技能和附件操作不能当作发送替代。
- 可识别弹窗存在时停止，不自动新建项目、确认或关闭弹窗。点击后出现弹窗则报告发送未确认，先检查平台是否收到内容再决定重试。
- 豆包发送/重试走 `PLATFORM_PREPARE_V2`，旧扩展监听器不识别该消息；工作台检查实际 manifest 版本，后台在准备图片/派发前核对豆包脚本 `adapterVersion=0.5.1`。三端需一致为 0.5.1，不覆盖注入已响应的旧脚本。
- 0.4.2 用户复测失败与 0.4.3 修正是历史证据，详见 [CF-010](../agent/CREATIVE_FLOW_ISSUES.md#cf-010豆包发送误触新建项目与弹窗遮挡)。

## 豆包结果：排除原图并合并尺寸

- 只采集本轮新模型回复 `receive_message` / `data-message-role=assistant` 内的 `message_image_content`，排除用户消息、输入/上传预览、导航、弹窗、SVG 占位和未完成图片。
- 用户原图发送后变成新 blob/CDN 地址仍按角色排除，并记入输入地址排除集；历史回复迟到加载的图片不算本轮结果。
- 同一豆包生成资产的 CDN、签名和缩略/完整尺寸合并，优先可见候选中像素最多的大图；工作台更新原卡，不重复追加，不把大图降回缩略图。
- 读取按 job、attempt、监控实例与取消/超时隔离；在途轮询不重叠，失败项可重试，不假报有效数量。
- 当前真实页只读核对为旧 4 元素→1 张 1792×1344 大图，原图未被选中；现存误收候选与归档不自动删除。详见 [CF-011](../agent/CREATIVE_FLOW_ISSUES.md#cf-011豆包结果过滤上传原图与同图重复尺寸)。

## 状态规则与记录

批次状态由子平台派生：全部 `completed` 才成功、全部取消才 `cancelled`、全部终态且有失败为 `failed`、全部排队为 `queued`，其他混合为 `running`。保留错误原因、attempt 和时间，允许单平台重试。取消只承诺本地停止监控，不承诺撤回远端生成。

真实验收需记录浏览器/扩展版本、平台 URL、jobId、attemptId、时间与错误截图/日志。没有真实结果证据时只记本地验证，不因清理文档而把平台验收关闭。
